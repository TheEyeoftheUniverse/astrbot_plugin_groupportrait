# 群像——AstrBot 群聊立绘插画插件（含 SillyTavern 扩展第二阶段）

## 目标与成功标准

AstrBot 插件「群像」（astrbot_plugin_groupportrait）：玩家把立绘上传绑定 QQ 号，管理员一条 `/群像` 触发——插件读取最近群聊上下文，交 LLM 构图（选场景、选出场角色、自动挑选绑定玩家的立绘作参考图、生成提示词），调用 RunningHub 工作流生成一幅群像插画，回发群里。第二阶段同思路移植为 SillyTavern（酒馆）扩展，共享构图提示词设计。

**成功标准**：
1. 群友发图 + `/立绘绑定` 成功绑定立绘，`/立绘查看` 可确认，换绑/解绑/管理员代管可用；
2. 管理员发 `/群像` 后，插件在无需任何人工干预的情况下完成「读上下文 → 构图 → 参考图选择 → RunningHub 生图 → 回发群里」全链路；
3. 出图能看出用了哪些玩家的立绘（形象一致性肉眼可辨）；
4. RunningHub 调用失败/超时有明确的群内错误提示，不静默吞掉。

## 功能需求（AstrBot 版 = 第一阶段）

### 1. 立绘绑定模块
- `/立绘绑定`（回复/引用一张图片发送，或先发图后紧跟指令）：把图片保存进插件数据目录，与发送者 QQ 号绑定。
- `/立绘换绑`：覆盖已有立绘；`/立绘解绑`：解除绑定；管理员可用 `/立绘代绑 @某人`（引用图片）代管、`/立绘清绑 @某人` 移除。
- `/立绘查看 [@某人]`：查看自己或他人的绑定状态（回显立绘缩略）。
- 存储：AstrBot 插件存储 API 存绑定表（QQ 号 → 图片文件名 + 元数据），图片按 QQ 号归档在插件数据目录。
- 图片规格校验：仅接受常见位图（png/jpg/webp），超大图拒绝（阈值做成配置，默认 10MB）；不做尺寸裁剪，原图即参考图。

### 2. 上下文采集
- 常规路径：触发时通过 OneBot 历史消息接口拉取本群最近 N 条（N 配置，默认 50）。
- 兜底路径：插件运行期维护每群滚动消息缓存（收到群消息时追加，含发送者 QQ/昵称/文本/时间），历史接口不可用时降级使用。
- 消息形态整理：纯文本保留；图片消息记为「[图片]」占位（不参与构图）；合并转发按一条摘要处理。

### 3. LLM 构图（结构化输出）
- 输入：整理后的最近消息（昵称 + QQ + 内容 + 时间），附当前群内已绑定立绘玩家清单（昵称 + QQ + 立绘编号）。
- 输出契约（JSON，插件负责解析与校验）：
  - `scene`: 场景与氛围描述（构图提示词主体）
  - `characters`: 出场角色数组，每项 `{qq, nickname, action, expression}`，≤4 项（D9）
  - `selected_refs`: 按 characters 顺序给出各角色使用的立绘文件标识
  - `negative`: 负面提示词（默认含「文字、水印、签名」，配合 D9 禁文字）
- 人数超员规则：绑定玩家 >4 时，LLM 只挑最近活跃者入画（prompt 中以活跃度标注辅助），插件层最后校验人数上限。
- LLM 输出解析失败/JSON 不合法：重试一次，仍失败则群内报错并附原因，不盲目出图。
- 系统提示词模板做成插件配置文件（模板含占位符），双端共享同一构图设计（酒馆版直接复用该模板）。

### 4. RunningHub 生图适配层
- 配置项：`api_key`（凭据注入或本地配置，禁明文入库）、`webappId`（占位工作流，D8）、节点映射（提示词节点 nodeId / 负面节点 nodeId / 参考图节点 nodeId 列表 / 比例字段）。
- 调用形态：`https://www.runninghub.cn/openapi/v2` 风格 webapp 调用（apiKey + webappId + nodeInfoList 覆盖字段），任务创建后轮询状态至完成，取结果图 URL。
- 参考图上传：立绘文件通过 RunningHub 上传接口预传，取回 asset id 填入 image 节点。
- 超时与错误：任务超时上限（配置，默认 5 分钟）、轮询间隔（默认 5s）、失败时群内报错文案。
- 实现时可参考现成客户端 `~/.hermes/scripts/runninghub_krea2.py`（登记表 70 条目 krea2-runninghub，keyRef runninghub/api_key）的 API 形态，但插件内自实现，不引入该脚本依赖。

### 5. 发图与命令面
- 命令一览：`/群像`（管理员，D11）、第 1 节绑定族命令。
- `/群像` 触发后立即回执「收到，正在画最近 N 条群聊的群像…（参与角色：A、B、C）」，生图完成后发图（可附带一行 LLM 生成的画面说明）。
- 生成中的重复触发：直接拒绝并提示剩余等待时间（冷却配置预留，默认关）。

### 6. 配置面板（AstrBot 插件配置体系）
- 分组：RunningHub（key/webappId/节点映射/超时）、构图（LLM 温度/上下文条数 N/系统提示词模板路径）、规格（比例/人数上限/张数）、权限（管理员名单/群白名单预留/冷却预留）。

## 第二阶段：SillyTavern 扩展（本阶段只立方向，不展开细节）

## 术语表
- **群像**：本插件名；一条命令生成的群聊场景插画。
- **立绘**：玩家上传的自定形象参考图；绑定后作为生图时的角色参考。
- **占位工作流**：先接通链路用的任意 RunningHub webapp 工作流（D8），后被正式工作流替换时只改配置不改代码。
- **构图提示词模板**：驱动 LLM 输出结构化构图的系统提示词文件，双端共享资产。

## 风险与备注
- **多人形象一致性是成图质量主要变量**：占位工作流阶段不追求一致；正式工作流必须带多图参考能力，选型见开放问题 2。
- OneBot 历史接口在不同协议端（NapCat/Lagrange）实现细节有差异，插件对字段缺失要容错（兜底缓存路径即为此设计）。
- RunningHub 按张计费：仅管理员触发（D6）即成本护栏；插件日志记录每次调用的 webappId 与任务 id，便于对账。
- 凭据纪律：api_key 不入 git 不入文档明文，走 AstrBot 配置存储或凭据注入。
